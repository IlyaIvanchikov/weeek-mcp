# Phase 4 — CRM: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every CRM operation of the WEEEK public API callable — funnels, statuses, deals, organizations, contacts, currencies: the 62 operations still deferred — as typed client methods and as 42 MCP tools in a new opt-in `crm` toolset, every reference by name or id, and release it as 1.0.0: the API is complete and the contract test's deferral list is gone.

**Architecture:** Each operation is one registry entry (`src/operations.ts`), one method on a resource client under `src/api/crm/` (funnels, statuses, deals, organizations, contacts, currencies, plus one `details` client for the address/email/phone routes the two owners share), and one tool in `src/tools/{funnels,deals,organizations,contacts,crm-links}.ts`. The resolver gains five kinds: `status` (opaque id, listed per funnel), `deal` (opaque id, searched per status — a funnel fans out over its statuses with bounded concurrency), `organization` and `contact` (UUID ids, server-side search), `currency` (integer, listed; matched by code). A new per-kind `lookup` capability lets `find` fetch an entry straight by id when the value looks like one, so a deal given by id needs no funnel or status, while a deal given by name does. Deal custom-field values reuse the Phase 3 encoder with the deal's funnel as the scope, and the `contact` field type now resolves names.

**Tech Stack:** TypeScript 5 (NodeNext ESM, `.js` import suffixes), Node ≥ 18, `@modelcontextprotocol/sdk` ^1.0 (1.29.0 installed), `zod` ^3.23 (3.25), `chrono-node` ^2.10, `vitest` 2 (2.1.9), GitHub Actions (tag-triggered publish).

**Spec:** `docs/superpowers/specs/2026-10-02-weeek-full-api-coverage-design.md` — §3.3 (toolsets), §3.4 (tool naming: add/remove pairs are two tools, every delete/detach gated), §4 (name resolution: the status, deal, organization, contact, currency and inline-detail rows; "Deals require context"), §5 (testing; §5.1 says Phase 4 deletes the `notYetImplemented` constant), §6 Phase 4 row.

## Facts found while planning (2026-10-14), which this plan rests on

Read-only probes of the live API (the token never left the probe script), plus the vendored spec:

- **Funnel, status and deal ids are opaque 16-character strings** (`OLY24hy2mC7n9D9l`, `XliVA5F0gguLo4Pw`, `EcwB3DpREwmffxSP`); **organization and contact ids are UUIDs**; currencies are integers 1–10 (`RUB`, `USD`, `EUR`, `GBP`, `CNY`, `UZS`, `PLN`, `AED`, `KZT`, `BYN`). The spec's §4 "opaque" fallback applies to all three CRM kinds, as Phase 3 found for funnels.
- **Envelopes:** `funnels` / `funnel`; `statuses` / `status`; `deals` + `hasMoreDeals` / `deal`; `organizations` / `organization` (no `hasMore` key); `contacts` / `contact` (no `hasMore` key); `currencies`; the detail routes answer `address` / `email` / `phone`; every other write answers `{ success }`.
- **Server-side search exists** on `GET /crm/statuses/{statusId}/deals`, `GET /crm/organizations`, `GET /crm/contacts` (`search`, `limit`, `offset`, `sort`); a nonsense search returns `[]`. The list filters typed as arrays (`assigneeIds`, `winStatuses`, `tags`, `organizations`, `contacts`, `customFields[*]`) have an undocumented encoding and are not exposed (same ruling as FOLLOWUPS 21 d).
- **Deals live only under a status**: no workspace-wide list, no funnel-wide list. `GET /crm/deals/{id}` exists, so a deal given by id needs no context.
- **A status carries no `funnelId`** and `GET /crm/statuses/{id}` does not add one; so `fields` on `weeek_create_deal` needs the funnel (name or id) to resolve field names, while `weeek_update_deal` reads it off the deal.
- **PUT replaces** for funnels (`name`, `currencyId`, `isPrivate`), organizations (`name`, `addresses`, `emails`, `phones`, `responsibles` — the detail arrays are plain strings) and contacts (`firstName` required). The update tools merge the scalar fields over the current object and **omit the detail arrays**; whether omitting them keeps the details is a smoke question (FOLLOWUPS 24 c). Details have their own routes and tools.
- **`POST /crm/deals/{id}/tasks` declares no body** and answers with a task. The tool sends `{ title, description? }`; what the API does with it is a smoke question (24 e).
- **`PUT /crm/deals/{id}`** (title, amount, winStatus, customFields) is a subset of **`PATCH /crm/deals/{id}`**; the tool uses PATCH. PUT gets a client method (`replace`) and a test, no tool — the one operation 1.0.0 leaves without a tool, on purpose.
- **Deal link bodies take one id each** (`assigneeId`, `contactId`, `organizationId`, `tag`); the assignee tools accept a list and call once per member.
- **0.7.0 is published**; the Phase 3 smoke (FOLLOWUPS 23) has not run yet. Phase 4's smoke (Task 9) runs on the local build before the tag and covers both lists.

## Global Constraints

- **Never commit without the user's explicit go-ahead.** Each task ends with a commit step; stop before it, show `git status --short` and the message, and wait. A blanket "approve all" from the user covers branch commits only — never a push, a PR, a tag or a publish.
- **Never `npm publish` by hand.** Pushing a `v*` tag triggers CI, which verifies `package.json` version == tag, publishes to npm and the MCP registry, and attaches the `.mcpb`.
- **Prerequisite:** 0.7.0 is tagged and published (done 2026-10-14). This plan branches from `main`: `git checkout main && git pull && git checkout -b feat/phase-4-crm`.
- Node ≥ 18 (`engines`), ESM only, every relative import ends in `.js`. No new runtime dependencies.
- Conventional Commits (commitlint): `type(scope): imperative subject`, lowercase, no trailing period.
- English-only code and comments. Match the existing comment density (a sentence of *why* at non-obvious spots, nothing else).
- Tests live in `tests/` and mirror `src/` one-to-one; fixtures are synthetic JSON shaped by `spec/weeek-openapi.json`'s component schemas; a value used both to build and to assert is declared once.
- No token in CI, in tests, or in any log line. The server must still boot and list tools without `WEEEK_API_TOKEN`.
- **Existing tools change additively only.** The 64 tool names of 0.7.0 stay; every parameter they have today keeps its name, type and meaning; new parameters are optional. The default toolset gains no tool.
- **Tool naming and safety (spec §3.4):** `weeek_<verb>_<noun>`; an add/remove (attach/detach) pair is two tools; every tool that deletes, removes or detaches requires `confirm: true` (`z.literal(true)`) and carries `destructiveHint: true`; `tests/tool-quality.test.ts` enforces the pair for every `weeek_delete_*`, `weeek_archive_*`, `weeek_detach_*`, `weeek_remove_*` name and caps descriptions at 600 characters.
- Every reference parameter (funnel, status, deal, organization, contact, currency, tag, member, detail) is `nameOrId`; an id passes through or is looked up, a name resolves. Task ids stay numeric.
- **Booleans the API wants as 0/1** (`isPrivate`) go through `apiFlag`.
- Closed sets get closed types (`as const` + derived union); exhaustive branches end in a `never` check; options objects for ≥ 3 params or same-typed params; constants in `src/api/constants.ts`, types in `src/api/types.ts`; normalisers take `unknown` through `asRecord`.
- Resolve everything, then write: a bad name never leaves a half-applied change. Every write tool calls `resolver.forget` for the kinds it dirtied.
- `spec/`, `scripts/`, `tests/`, `docs/` are not shipped: `package.json` `files` stays `["dist"]`.

## Review Focus

1. **A deal given by name without a funnel or a status** must fail with a message naming what is missing, never search the whole workspace; a deal given by its 16-character id must resolve with no context at all. → tests in Task 6 (`deal` kind) and Task 7 (`weeek_get_deal`).
2. **A deal name that exists in two statuses of the funnel** must fail with both as candidates, not pick the first status's. → test in Task 6 (fan-out merge feeds `pickUniqueEntry`).
3. **An organization update must not wipe its addresses, emails or phones**: `weeek_update_organization { organization, name }` sends `name` and the current `responsibles` and omits the three detail arrays. → test in Task 8; FOLLOWUPS 24(c) verifies the API keeps them.
4. **A detail named by its value** (`weeek_delete_detail { organization: "Acme", kind: "email", detail: "kot@gmail.com" }`) resolves from the organization's inline list with no extra call, and an address on a contact is refused before any call (contacts have no addresses). → tests in Task 8.
5. **`weeek_move_deal` sends exactly the request the arguments mean**: `to_funnel` → `PUT …/funnel`; `to_status` alone → `PUT …/status`; `after` → `POST …/move` with `statusId` and `previousDealId` (null for the first position); none of the three → rejected before any call. → tests in Task 7.
6. **`fields` on `weeek_create_deal` without `funnel`** fails before any call with a message saying the funnel is needed for field names; on `weeek_update_deal` the deal's own `funnelId` is the scope. → tests in Task 7.

`src/errors.ts` — `ResolutionError`:

```ts
export class ResolutionError extends Error {
  constructor(public kind: string, public query: string, public candidates: Candidate[], hint?: string) {
    const list = candidates.length
      ? candidates.map((c) => `${c.name} (id ${c.id})`).join(", ")
      : "none";
    super(`could not resolve ${kind} "${query}"; candidates: ${list}${hint === undefined ? "" : ` — ${hint}`}`);
    this.name = "ResolutionError";
  }
}
```

```ts
export type FieldScopeKind = (typeof fieldScopes)[number];
/** The id each scope kind is addressed by; a kind added to fieldScopes without a row here fails to compile. */
interface FieldScopeOwners { global: Record<never, never>; project: { projectId: number }; board: { boardId: number }; funnel: { funnelId: string }; }
/** Where a custom field lives. Each scope has its own routes, so the variant carries the owner's id. */
export type FieldScope = { [K in FieldScopeKind]: { kind: K } & FieldScopeOwners[K] }[FieldScopeKind];
/** Where a global, project or board field can be sent. */
export type TransferTarget = Extract<FieldScope, { kind: (typeof transferTargetKinds)[number] }>;
```

/** The entity, or null when the API answers 404 — how an id-shaped value is tried before a search. */
export async function orNullWhenMissing<T>(request: Promise<T>): Promise<T | null> {
  try {
    return await request;
  } catch (err) {
    if (err instanceof WeeekApiError && err.status === 404) return null;
    throw err;
  }
}

/** First, middle and last name joined with single spaces, blanks skipped — how members and contacts are named. */
export function fullName(raw: unknown): string {
  const r = asRecord(raw);
  return [r.firstName, r.middleName, r.lastName].filter(Boolean).map(String).join(" ").trim();
}

/** A wire list as strings; anything that is not a list is empty. */
export function stringList(value: unknown): string[] {
  return Array.isArray(value) ? value.map(String) : [];
}

export function toMember(raw: unknown): Member {
  const r = asRecord(raw);
  const name = fullName(r) || r.name || r.email || String(r.id ?? "");
  return { id: String(r.id ?? ""), name: String(name) };
}

export function toFunnel(raw: unknown): Funnel {
  const r = asRecord(raw);
  return {
    id: String(r.id ?? ""),
    name: String(r.name ?? ""),
    currencyId: r.currencyId == null ? null : Number(r.currencyId),
    isPrivate: Boolean(r.isPrivate),
    dealsCount: Number(r.dealsCount ?? 0),
    dealsAmount: Number(r.dealsAmount ?? 0),
    team: stringList(r.team),
    customFields: Array.isArray(r.customFields) ? r.customFields.map(toCustomField) : [],
  };
}

export class FunnelsApi {
  constructor(private http: HttpClient) {}

  async list(): Promise<Funnel[]> {
    const json = await this.http.execute<Record<string, unknown>>(ops.list);
    return pickArray(json, "funnels").map(toFunnel);
  }

  async get(funnelId: string): Promise<Funnel> {
    const json = await this.http.execute<{ funnel: unknown }>(ops.get, { params: { funnelId } });
    return toFunnel(json.funnel);
  }

  async create(newFunnel: NewFunnel): Promise<Funnel> {
    const json = await this.http.execute<{ funnel: unknown }>(ops.create, { body: { ...newFunnel, isPrivate: apiFlag(newFunnel.isPrivate) } });
    return toFunnel(json.funnel);
  }

  async update({ funnelId, update }: UpdateFunnelOptions): Promise<Funnel> {
    const json = await this.http.execute<{ funnel: unknown }>(ops.update, { params: { funnelId }, body: { ...update, isPrivate: apiFlag(update.isPrivate) } });
    return toFunnel(json.funnel);

import type { HttpClient, PathParams } from "../../http.js";
import { operations, type Operation } from "../../operations.js";
import { asRecord } from "../responses.js";
import type { Detail, DetailKind, DetailOwner, SuccessResponse } from "../types.js";

export interface DetailRef { owner: DetailOwner; kind: DetailKind; }
export interface AddDetailOptions extends DetailRef { value: string; }
export interface UpdateDetailOptions extends DetailRef { detailId: string; value: string; }
export interface RemoveDetailOptions extends DetailRef { detailId: string; }

interface DetailRoutes { add: Operation; update: Operation; remove: Operation; }

// A contact has no addresses; the null says so where the routes live, and the methods refuse it before any request.
const routes: Record<DetailOwner["kind"], Record<DetailKind, DetailRoutes | null>> = {
  organization: {
    address: { add: operations.organizations.addAddress, update: operations.organizations.updateAddress, remove: operations.organizations.removeAddress },
    email: { add: operations.organizations.addEmail, update: operations.organizations.updateEmail, remove: operations.organizations.removeEmail },
    phone: { add: operations.organizations.addPhone, update: operations.organizations.updatePhone, remove: operations.organizations.removePhone },
  },
  contact: {
    address: null,
    email: { add: operations.contacts.addEmail, update: operations.contacts.updateEmail, remove: operations.contacts.removeEmail },
    phone: { add: operations.contacts.addPhone, update: operations.contacts.updatePhone, remove: operations.contacts.removePhone },
  },
};

function ownerParams(owner: DetailOwner): PathParams {
  switch (owner.kind) {
    case "organization": return { organizationId: owner.id };
    case "contact": return { contactId: owner.id };
    default: { const _exhaustive: never = owner.kind; throw new Error(`unhandled detail owner ${String(_exhaustive)}`); }
  }
}

function routesOf({ owner, kind }: DetailRef): DetailRoutes {
  const found = routes[owner.kind][kind];
  if (found === null) throw new Error(`a ${owner.kind} has no ${kind}es; only organizations do`);
  return found;
}

/** One detail as the API answers it: `{ id, <kind>: value }`. */
export function toDetail(raw: unknown, kind: DetailKind): Detail {
  const r = asRecord(raw);
  return { id: String(r.id ?? ""), value: String(r[kind] ?? "") };
}

export function toDetails(list: unknown, kind: DetailKind): Detail[] {
  return Array.isArray(list) ? list.map((item) => toDetail(item, kind)) : [];
}

/** Addresses, emails and phones of organizations and contacts — the same three verbs over two owners. */
export class DetailsApi {
  constructor(private http: HttpClient) {}

  async add({ owner, kind, value }: AddDetailOptions): Promise<Detail> {
    const json = await this.http.execute<Record<string, unknown>>(routesOf({ owner, kind }).add, { params: ownerParams(owner), body: { [kind]: value } });
    return toDetail(json[kind], kind);
  }

  async update({ owner, kind, detailId, value }: UpdateDetailOptions): Promise<Detail> {
    const json = await this.http.execute<Record<string, unknown>>(routesOf({ owner, kind }).update, { params: { ...ownerParams(owner), [`${kind}Id`]: detailId }, body: { [kind]: value } });
    return toDetail(json[kind], kind);
  }

  async remove({ owner, kind, detailId }: RemoveDetailOptions): Promise<SuccessResponse> {
    return this.http.execute<SuccessResponse>(routesOf({ owner, kind }).remove, { params: { ...ownerParams(owner), [`${kind}Id`]: detailId } });
  }
}

export interface OrganizationContactOptions { organizationId: string; contactId: string; }

export function toOrganization(raw: unknown): Organization {
  const r = asRecord(raw);
  return {
    id: String(r.id ?? ""),
    name: String(r.name ?? ""),
    responsibleId: r.responsibleId == null ? null : String(r.responsibleId),
    addresses: toDetails(r.addresses, "address"),
    emails: toDetails(r.emails, "email"),
    phones: toDetails(r.phones, "phone"),
    contacts: stringList(r.contacts),
    tags: Array.isArray(r.tags) ? r.tags.map(Number) : [],
  };
}

/** The API sends no "more" flag for organizations and contacts: a full page, when one was asked for, means there may be more. */
export function pageHasMore(count: number, limit: number | undefined): boolean {
  return limit !== undefined && count >= limit;
}

export class OrganizationsApi {
  constructor(private http: HttpClient) {}

  async list(query: CrmQuery = {}): Promise<OrganizationPage> {
    const json = await this.http.execute<Record<string, unknown>>(ops.list, { query });
    const organizations = pickArray(json, "organizations").map(toOrganization);
    return { organizations, hasMore: pageHasMore(organizations.length, query.limit) };
  }

  async get(organizationId: string): Promise<Organization> {
    const json = await this.http.execute<{ organization: unknown }>(ops.get, { params: { organizationId } });
    return toOrganization(json.organization);
  }

    return orNullWhenMissing(this.get(organizationId));

    const json = await this.http.execute<{ organization: unknown }>(ops.create, { body: newOrganization });
    return toOrganization(json.organization);

    const json = await this.http.execute<{ organization: unknown }>(ops.update, { params: { organizationId }, body: update });
    return toOrganization(json.organization);

    return this.http.execute<SuccessResponse>(ops.remove, { params: { organizationId } });
  }

/** `items.map(fn)` with at most `limit` mappers in flight; results keep the input order. */
export async function mapWithLimit<T, R>(items: readonly T[], limit: number, fn: (item: T) => Promise<R>): Promise<R[]> {
  const results: R[] = new Array(items.length);
  let next = 0;
  const worker = async (): Promise<void> => {
    while (next < items.length) {
      const index = next;
      next += 1;
      results[index] = await fn(items[index]);
    }
  };
  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, worker));
  return results;
}

  /** The entry a name or an id denotes — the whole thing, for callers that need more than the id. */
  async find<K extends KindName>({ kind, value, scope = {} }: ResolveOptions<K>): Promise<EntryOf<K>> {
    const query = String(value).trim();
    const kindDefinition: Kind = kinds[kind];
    const found = await kindDefinition.lookup?.(this.client, query);
    // The kind that answered a lookup is the kind asked for; the union hides that from the compiler.
    if (found) return found as unknown as EntryOf<K>;
    const entries = await this.load(kind, scope, query);
    return Resolver.pickEntry(kindDefinition.label, query, entries);
  }

export interface DealContext { funnelId?: string; statusId?: string; }

export async function resolveDealContext(resolver: Resolver, { funnel, status }: Pick<DealRefArgs, "funnel" | "status">): Promise<DealContext> {
  const funnelId = funnel === undefined ? undefined : await resolver.resolve({ kind: "funnel", value: funnel });
  const statusId = status === undefined ? undefined : await resolver.resolve({ kind: "status", value: status, scope: { funnelId } });

import { z } from "zod";
import type { ToolContext } from "../toolsets/types.js";
import type { WeeekClient } from "../client.js";
import { Resolver } from "../resolver.js";
import { detailKinds } from "../api/constants.js";
import type { Contact, Detail, DetailKind, DetailOwner, Organization } from "../client.js";
import { destructiveAnnotations } from "./constants.js";
import { confirmation, nameOrId } from "./inputs.js";
import { registerJsonTool } from "./json-tool.js";
import { crmOwnerShape, dealRef, findDeal, resolveCrmOwner, type CrmOwner } from "./crm-refs.js";

type ContactHost = Exclude<CrmOwner, { kind: "contact" }>;

const contactLinkShape = { contact: nameOrId.describe("The contact, by full name or id."), deal: dealRef.deal.optional(), funnel: dealRef.funnel, status: dealRef.status, organization: nameOrId.optional() };
type ContactLinkArgs = z.infer<z.ZodObject<typeof contactLinkShape>>;

/** The deal or the organization a contact is linked to — exactly one. */
async function resolveContactHost(resolver: Resolver, args: ContactLinkArgs): Promise<ContactHost> {
  if ((args.deal === undefined) === (args.organization === undefined)) throw new Error("pass exactly one of deal or organization");
  if (args.deal !== undefined) return { kind: "deal", id: (await findDeal(resolver, { deal: args.deal, funnel: args.funnel, status: args.status })).id };
  return { kind: "organization", id: await resolver.resolve({ kind: "organization", value: args.organization as string | number }) };
}

/** The owner's fresh object, for tools that return what they changed. */
async function readOwner(client: WeeekClient, owner: CrmOwner): Promise<unknown> {
  switch (owner.kind) {
    case "deal": return client.crm.deals.get(owner.id);
    case "organization": return client.crm.organizations.get(owner.id);
    case "contact": return client.crm.contacts.get(owner.id);
    default: { const _exhaustive: never = owner; throw new Error(`unhandled owner ${String(_exhaustive)}`); }
  }
}

const detailOwnerShape = { organization: nameOrId.optional().describe("The organization, by name or id."), contact: nameOrId.optional().describe("The contact, by full name or id.") };
const detailKind = z.enum(detailKinds);
type DetailOwnerArgs = z.infer<z.ZodObject<typeof detailOwnerShape>> & { kind: DetailKind };
interface FoundDetailOwner { owner: DetailOwner; entity: Organization | Contact; }

/** The organization or the contact the detail belongs to, with its current details; an address on a contact is refused before any call. */
async function findDetailOwner(resolver: Resolver, args: DetailOwnerArgs): Promise<FoundDetailOwner> {
  if ((args.organization === undefined) === (args.contact === undefined)) throw new Error("pass exactly one of organization or contact");
  if (args.organization !== undefined) {
    const entity = await resolver.find({ kind: "organization", value: args.organization });
    return { owner: { kind: "organization", id: entity.id }, entity };
  }
  if (args.kind === "address") throw new Error("a contact has no addresses; only organizations do");
  const entity = await resolver.find({ kind: "contact", value: args.contact as string | number });
  return { owner: { kind: "contact", id: entity.id }, entity };
}

function detailsOf(entity: Organization | Contact, kind: DetailKind): Detail[] {
  switch (kind) {
    case "address": return "addresses" in entity ? entity.addresses : [];
    case "email": return entity.emails;
    case "phone": return entity.phones;
    default: { const _exhaustive: never = kind; throw new Error(`unhandled detail kind ${String(_exhaustive)}`); }
  }
}

/** A detail by its value or id, from the owner's own list — no API call. */
function pickDetail({ entity }: FoundDetailOwner, kind: DetailKind, value: string | number): Detail {
  const named = detailsOf(entity, kind).map((detail) => ({ id: detail.id, name: detail.value }));
  const picked = Resolver.pickEntry(`${kind} of ${entity.name}`, String(value), named);
  return { id: picked.id, value: picked.name };
}

/** Links shared by deals, organizations and contacts: contacts, tags, and the address/email/phone details. */
export function registerCrmLinkTools({ server, client, resolver }: ToolContext): void {
  registerJsonTool(server, "weeek_attach_contact", {
    description: "Link a CRM contact (by full name or id) to a deal (by id, or by title with `funnel`/`status`) or to an organization (by name or id) — exactly one. Returns the deal or organization.",
    inputSchema: contactLinkShape,
  }, async (args) => {
    const host = await resolveContactHost(resolver, args);
    const contactId = await resolver.resolve({ kind: "contact", value: args.contact });
    if (host.kind === "deal") await client.crm.deals.addContact({ dealId: host.id, contactId });
    else await client.crm.organizations.addContact({ organizationId: host.id, contactId });
    resolver.forget({ kind: host.kind });
    return readOwner(client, host);
  });

  registerJsonTool(server, "weeek_detach_contact", {
    description: "Unlink a CRM contact from a deal or an organization (exactly one). Requires confirm:true. Returns the deal or organization.",
    inputSchema: { ...contactLinkShape, confirm: confirmation },
    annotations: destructiveAnnotations,
  }, async (args) => {
    const host = await resolveContactHost(resolver, args);
    const contactId = await resolver.resolve({ kind: "contact", value: args.contact });
    if (host.kind === "deal") await client.crm.deals.removeContact({ dealId: host.id, contactId });
    else await client.crm.organizations.removeContact({ organizationId: host.id, contactId });
    resolver.forget({ kind: host.kind });
    return readOwner(client, host);
  });

  registerJsonTool(server, "weeek_add_crm_tag", {
    description: "Put a workspace tag (by title or id) on a deal, an organization or a contact — exactly one. Returns the tagged object.",
    inputSchema: { tag: nameOrId, ...crmOwnerShape },
  }, async (args) => {
    const owner = await resolveCrmOwner(resolver, args);
    const tagId = await resolver.resolve({ kind: "tag", value: args.tag });
    switch (owner.kind) {
      case "deal": await client.crm.deals.addTag({ dealId: owner.id, tagId }); break;
      case "organization": await client.crm.organizations.addTag({ organizationId: owner.id, tagId }); break;
      case "contact": await client.crm.contacts.addTag({ contactId: owner.id, tagId }); break;
      default: { const _exhaustive: never = owner; throw new Error(`unhandled owner ${String(_exhaustive)}`); }
    }
    resolver.forget({ kind: owner.kind });
    return readOwner(client, owner);
  });

  registerJsonTool(server, "weeek_remove_crm_tag", {
    description: "Take a workspace tag (by title or id) off a deal, an organization or a contact — exactly one. Requires confirm:true. Returns the object.",
    inputSchema: { tag: nameOrId, ...crmOwnerShape, confirm: confirmation },
    annotations: destructiveAnnotations,
  }, async (args) => {
    const owner = await resolveCrmOwner(resolver, args);
    const tagId = await resolver.resolve({ kind: "tag", value: args.tag });
    switch (owner.kind) {
      case "deal": await client.crm.deals.removeTag({ dealId: owner.id, tagId }); break;
      case "organization": await client.crm.organizations.removeTag({ organizationId: owner.id, tagId }); break;
      case "contact": await client.crm.contacts.removeTag({ contactId: owner.id, tagId }); break;
      default: { const _exhaustive: never = owner; throw new Error(`unhandled owner ${String(_exhaustive)}`); }
    }
    resolver.forget({ kind: owner.kind });
    return readOwner(client, owner);
  });

  registerJsonTool(server, "weeek_add_detail", {
    description: "Add an address, email or phone (`kind`) to a CRM organization or contact (exactly one; contacts have no addresses).",
    inputSchema: { ...detailOwnerShape, kind: detailKind, value: z.string().min(1) },
  }, async (args) => {
    const { owner } = await findDetailOwner(resolver, args);
    const detail = await client.crm.details.add({ owner, kind: args.kind, value: args.value });
    resolver.forget({ kind: owner.kind });
    return detail;
  });

  registerJsonTool(server, "weeek_update_detail", {
    description: "Change one address, email or phone of a CRM organization or contact: `detail` is its current value or id, `value` the new one.",
    inputSchema: { ...detailOwnerShape, kind: detailKind, detail: nameOrId, value: z.string().min(1) },
  }, async (args) => {
    const found = await findDetailOwner(resolver, args);
    const detail = await client.crm.details.update({ owner: found.owner, kind: args.kind, detailId: pickDetail(found, args.kind, args.detail).id, value: args.value });
    resolver.forget({ kind: found.owner.kind });
    return detail;
  });

  registerJsonTool(server, "weeek_delete_detail", {
    description: "Remove one address, email or phone (`detail`: its current value or id) from a CRM organization or contact. Irreversible; requires confirm:true.",
    inputSchema: { ...detailOwnerShape, kind: detailKind, detail: nameOrId, confirm: confirmation },
    annotations: destructiveAnnotations,
  }, async (args) => {
    const found = await findDetailOwner(resolver, args);
    const removal = await client.crm.details.remove({ owner: found.owner, kind: args.kind, detailId: pickDetail(found, args.kind, args.detail).id });
    resolver.forget({ kind: found.owner.kind });
    return removal;
  });
}
